# 前端加密方案（include 一小段 JS + front matter 存密文）

## 核心原则：加密代码两端同源
所有加密/解密逻辑**只使用浏览器 Web Crypto API**（`crypto.subtle` 的 PBKDF2/AES-GCM、`TextEncoder` 等）。本地 Node 工具（Node 18+ 全局自带 `crypto.subtle`，本机 v24 已确认）与浏览器 include 里是**同一份函数代码**，不用任何 `node:crypto` 加密接口；Node 只做文件读写、口令输入等 I/O。

## 加密后的文章（提交到 git 的样子）
```markdown
---
layout: post
title: The Queens Clown
cipher: ENC1.salt.iv.ciphertext
---
```
正文为空。三段均为 base64url：PBKDF2-HMAC-SHA256(150k 轮) 派生 256 位密钥 → AES-256-GCM（12B IV，密文含认证标签）。错误口令解密直接失败。43 篇旧文章完全不动。

## 改动清单（2 个新文件 + 1 处 3 行改动）

**1. `_layouts/post.html`**（唯一修改的现有文件）：
```liquid
{% if page.cipher %}{% include encrypted-post.html %}{% else %}{{ content }}{% endif %}
```

**2. `_includes/encrypted-post.html`**（新增，核心就这一段 JS）：
- 隐藏 `<div>{{ page.cipher }}</div>` + 口令输入框 + 解密按钮 + 错误提示（表单样式内联，几行）
- 点击/回车 → Web Crypto（PBKDF2 + AES-GCM）解密 → marked 渲染 Markdown → 替换 DOM 显示
- marked 用 CDN 一行 `<script>` 引入（如 CDN 不可达再改为 vendor 进 public/）
- 口令存 sessionStorage：同一浏览器会话内看其他加密文章自动解密（3-4 行，可选）
- 解密失败显示"口令错误"

**3. `crypt.js`**（新增，仓库根目录，约 80 行）：
- `node crypt.js encrypt _posts/2026-08-16-xxx.md`：提示输口令（隐藏输入），自动从文件名生成 title（去日期前缀、`-`→空格、英文首字母大写、中文原样），保留 author/source/categories 等 front matter，正文 CRLF 归一后加密，cipher 写进 front matter、清空正文
- `node crypt.js decrypt _posts/xxx.md`：反向还原明文便于编辑
- 加密函数与 include 里的代码逐字相同（同一段可复制）

## 不用动的文件
atom.xml（正文为空，RSS 天然干净）、index.html（本来就只列标题）、Related posts、Disqus、styles.scss、_config.yml。无插件，GitHub Pages 原生构建。

## 验证
1. Node 端 round-trip：加密 → 解密还原，中文/CRLF/front matter 保留均一致
2. 端到端：用 include 里那份相同的解密函数跑工具产出的密文，确认可解
3. 造一篇示例加密文章，浏览器实测：正确口令渲染、错误口令提示、旧文章不受影响（用 browser 工具核验）

## 说明
- 标题/日期/author/source 仍是明文（符合"标题显示文件名去日期"的要求）；正文保密强度取决于口令强度
- 编辑期间（解密状态）不要 commit
